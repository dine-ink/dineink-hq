Critical — App-breaking bugs
Critical
Kitchen shows 0 data — RunningOrder is hard-deleted on billing
runningOrders.service.ts · backend

This is the root cause of the reported kitchen bug. When a bill is generated, closeRunningOrderService calls prisma.runningOrder.deleteMany() — completely wiping the row and all batches/items. The kitchen query filters where: { status: "ACTIVE" }, finds nothing (because the rows are gone), and returns 0 results. Bills exist, kitchen is empty.

FixUpdate closeRunningOrderService to set status: "CLOSED" (or "BILLED") instead of deleting. The kitchen query already filters on status: "ACTIVE" — just stop deleting the rows.
Critical
paymentMode vs paymentMethod — every DineIn bill fails to save
bills.service.ts · backend

The service destructures paymentMode from the request body, but all frontend callers send paymentMethod. So paymentMode is always undefined, and the bill is stored with paymentMethod: undefined. Since paymentMethod is a non-nullable field on the Bill model, Prisma throws a validation error on every bill creation via this path.

FixChange the destructure in createBillService from paymentMode to paymentMethod and remove the internal remap.
Critical

Quick_Takeaway_Billing.tsx · pos

Result: takeaway orders never appear in Reports, P&L, or Bills pages. The printed bill number always falls back to BILL-{Date.now()} because the response has no billNumber field.

FixRoute takeaway/quick confirm through closeRunningOrder just like DineIn, which actually creates the Bill and handles ingredient deduction.

Critical
Table set AVAILABLE outside transaction — stays free if bill creation fails
runningOrders.service.ts · backend

In closeRunningOrderService, the Promise.all that sets the table to AVAILABLE and upserts the customer runs before the prisma.$transaction block. If the transaction fails (e.g. Prisma validation error from Bug #2 above), the table is permanently stuck as AVAILABLE even though no bill was created and the order is still active. Staff will seat new customers at an occupied table.

FixMove the table status update inside the $transaction block so it rolls back atomically if the bill creation fails.

High

analyticsAdvanced.service.ts vs analytics.service.ts · backend

buildDateFilter appends a literal UTC Z suffix (T23:59:59.999Z), while getDateRange uses setHours(23,59,59,999) in the server's local timezone.
